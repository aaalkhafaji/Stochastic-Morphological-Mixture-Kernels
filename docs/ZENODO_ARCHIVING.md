# Archive this release with Zenodo

1. Publish this directory as the GitHub repository content using Git or GitHub Desktop.
2. Review `LICENSE_NOTICE.md` before calling the project open source; no new project license has been selected in this package.
3. In Zenodo, connect the authors' GitHub account and enable this repository.
4. Create a versioned GitHub release/tag, recommended tag: `v2.1.0`.
5. Zenodo will archive the release. The repository contains both `CITATION.cff` and `.zenodo.json`; Zenodo uses `.zenodo.json` for GitHub-release metadata when both are present.
6. After Zenodo mints the DOI, add the real DOI and repository URL to the next metadata revision and to the manuscript data/code availability statement. Do not retroactively invent identifiers in the frozen v2.1.0 bytes.

A separate self-contained manual-upload archive, `JVCIR_Zenodo_Archive_v2.1.0.zip`, is also prepared alongside the GitHub ZIP.
